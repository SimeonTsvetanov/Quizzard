- 2026-11-22 · **T-02 take-over of the 2025 site — what is there:** the live site is branch `gh-pages` (pushed 2025-06-27 by `peaceiris/actions-gh-pages` from the old `pages.yml`), so the Pages source is "Deploy from a branch". Its worker `/Quizzard/service-worker.js` (scope `/Quizzard/`) answers every request network-first, calls `skipWaiting` + `clients.claim`, and on activate deleted every other cache of the shared origin. The whole `legacy-2025` history used 9 cache names (`app.config.legacyCacheNames`); `manifest.json` had no `id`, `start_url` = `scope` = `/Quizzard/`. Saved data: localStorage `quizzard_*`/`quizzard-*` keys and IndexedDB `QuizzardDB`. · Read with `git show` on both branches and `curl` of the live files.
- 2026-11-22 · **T-02 service worker:** the new worker is served at the 2025 URL `service-worker.js` (vite-plugin-pwa `filename`; never renamed, pwa §3) and imports `sw-handover.js` (scripts/sw-handover.ts, emitted by app/vite.config.ts): on install it skips waiting only when a 2025 cache exists; on activate it deletes exactly those 9 names — never another app's cache, this app's Workbox caches, localStorage or IndexedDB (DECISIONS clean slate: 2025 data is not read, migrated or deleted). Because the 2025 worker is network-first, the first start after the deploy already shows the new app; the take-over happens under it, and app/src/pwa.ts offers no Reload for that one controller change (a page that started with a 2025 cache already runs the new version). Every later update waits for Reload (pwa §5). · pwa §11: 2025 pages cannot ask for skip-waiting, so the new worker would otherwise wait until every window closes. Proved by tests/e2e/legacy-2025.spec.ts with the real 2025 worker (fixtures from `gh-pages`): one reload → new app, controlled by the new worker, no waiting worker, no 2025 cache, no Reload offer, another app's cache and the 2025 data kept, offline start works. Test seam: `vite preview` serves the 2025 page, worker and manifest while the cookie `e2e-legacy-2025=1` is set.
- 2026-11-22 · **T-02 manifest identity:** `id` = `start_url` = `scope` = `/Quizzard/`, and the file keeps its 2025 URL `manifest.json` (vite-plugin-pwa `manifestFilename`) · without an `id` Chrome took `start_url` as the identity, so `/Quizzard/` is the same app; developer.chrome.com "pwa-manifest-id" (read 2026-11-22): nothing breaks "as long as the start_url and the manifest path remains the same". Installed copies then update name, colours and icons through Chrome's manifest update (iOS only on reinstall). Consequences: `manifest.json` is excluded from the precache glob (the plugin lists it itself; the duplicate entry with another revision stopped Workbox's precache — caught by the e2e); GitHub Pages serves it as `application/json`, not `application/manifest+json` (pwa §9 check differs; browsers accept both).
