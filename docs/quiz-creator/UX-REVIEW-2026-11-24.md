## What already works well (keep)

- The destructive logic of the creator is mostly right: quiz and round delete ask only when something is lost; Cancel left /
  Delete right; one destructive red; initial focus on Cancel; Escape returns focus to the trigger; Undo puts the quiz, round or
  question back in place (a quiz with its media). Library delete returns focus to "New quiz".
- Question delete is one tap + Undo (forge rule: small item = no dialog + Undo), focus goes to the neighbour card.
- "Apply to all" confirms with the number of affected questions and offers Undo. "From the round" / "Back to the round's: 30 s" is a good
  pattern and does not move anything when it swaps.
- Limits explain themselves (8 options at most, 20 rounds, 50 questions); "Not finished" chip on cards; media meter; > 100 MB export
  warning; "Saved" tick; the phone live preview is pinned under the header.
- No sideways scroll on any creator screen at 320 px with 200 % root font and WCAG 1.4.12 text spacing, nor at 360–1920 (measured
  `scrollWidth - innerWidth = 0`).

# MUST FIX

### M1 · Host panel: the "Next" button is white on white while the mouse is over it
- Where: host panel (audience window open), 1280×860, light and dark, EN/BG. `ux-host-panel-1280-en-light.png` (bottom button is an
  empty white pill), `ux-host-next-hover.png`.
- What: computed style on hover = `background oklch(1 0 0)` / `color oklch(1 0 0)`; idle = purple / white. The rule
  `.qp-panel .qp-bar-button:hover:not(:disabled)` (specificity 0,4,0) beats `[data-primary]` (0,3,0): hovering the primary button turns it
  into the surface colour while the label keeps the on-accent (white) colour. The host loses the label of the most important button
  whenever the pointer is over it. WCAG 1.4.3 (1:1).
- Fix: `player/src/styles/panel.css` lines 14–24: `&:hover:not(:disabled):not([data-primary])`, and give `[data-primary]:hover` a
  darker accent (as `chrome.css` does with gold). Check `:active` too. S.

### M2 · Focus falls to `<body>` after moves (phone) and at the ends of the player bar
- Where: creator at 390 px (a round is a page of its own); player bar and host panel at any width.
- What (measured with `document.activeElement`): open a round from its card → BODY; "Add round" → BODY; "Duplicate round" → BODY (all
  390 px). On 1280 px focus stays on the *quiz* `<h2>` after opening another round, so a screen-reader user hears nothing about the round
  that opened. Player: keyboard focus on "Next" at the last screen (it becomes `disabled`) → BODY; same for "Back" at the start and for
  timer/restart buttons on screens without a timer (`ui/bar.ts` and `ui/panel.ts` `update()` set `disabled`). WCAG 2.4.3; forge
  accessibility §3 (never lose focus to body; prefer `aria-disabled` over `disabled` on a focused control).
- Fix: (a) `screens/quiz.ts openRound()`, the "Add round" handler, `screens/round-settings.ts copyRound()` and `removeRound()`: pass the focus
  selector as the third argument of `app.go(...)`, e.g. `'#quiz-round-title'` (the hidden `h2[tabindex=-1]` already exists in `round.ts`);
  on wide too, so the pane change is announced. (b) `ui/bar.ts`, `ui/panel.ts`: `aria-disabled="true"` + ignore the click for
  Back/Next/timer/reset instead of `disabled`. S.

### M3 · During Play on a phone the shell header and skip link stay tabbable behind the full-screen stage
- Where: `quiz:play` scenario, 390 px: **FAIL 2.4.11 "focused element not fully obscured"** — "Back to Home", "Quizzard — home", "Open
  menu" are under `div.qp-view`. My own Tab walk: Back to the quiz → Next → Menu → Skip to content → Back to Home (covered) → Quizzard home
  (covered) → Open menu (covered).
- Why: keyboard and switch users land on invisible controls; one Enter leaves the game.
- Fix: while route = `play`, mark everything outside the player `inert` (shell `<header>`, skip link, footer) in `screens/play.ts` /
  `app/mount.ts` and remove it on leave; or `visibility:hidden` on the shell header while `[data-screen="play"]`. S.

### M4 · Media: Remove and Replace destroy a processed file at once — no confirm, no Undo; switching kind drops the file silently
- Where: editor of a picture/audio/video question, any viewport. `ux-editor-picture-set-1280-en-light.png`.
- What: "Remove" removes the file reference immediately and moves focus to "Choose a picture"; "Replace" overwrites immediately. No toast
  (measured: no status after remove). A downscaled photo or a 40 MB clip cannot be got back without the original. Changing Audio → Video
  (measured) or Picture → Text also drops the reference without a word. Inconsistent with question delete (Undo) and quiz delete (keeps
  blobs for Undo). Forge ui-patterns: irreversible delete/replace asks first or offers Undo.
- Fix: `screens/editor-files.ts remove()` and `pick()`: `offerUndo(app, t("media.removed"|"media.replaced"), restore, redraw)` where
  `restore` re-points the question at the previous `{ media: { id } }` and entry; keep the old blob in the store until the toast is gone (the
  library does this for quizzes: `app.store.media(...)`, `app.view.swept`). Same toast when a kind change detaches a file
  ("Picture removed · Undo"). M.

### M5 · "Open a quiz file" over an existing quiz: Replace has no Undo, the dialog has no Cancel, Escape does something
- Where: library, any width, a file whose quiz id exists. `ux-confirm-openfile-1280-en-light.png`.
- What: the dialog offers only "Keep both" and "Replace" (red). Escape or a tap on the backdrop = "Keep both": a copy is created and the app
  leaves the library for it (measured: library cards = 0 afterwards). There is no way to say "wrong file, do nothing". "Replace" overwrites the
  person's newer work (in the test their copy was changed later) and has no Undo (`file.replaced` toast has no action). The dates in the text
  use two formats: "changed Nov 23, 2026; yours was changed 06:25 AM". HIG: always offer Cancel; Escape = cancel.
- Fix: `quizfile/open.ts askReplace()`: Cancel (default focus, Escape), Keep both, Replace (danger). The shell `confirm` has one confirm + one
  cancel, so either two sequential questions ("Replace yours?" Cancel / Replace; on Cancel the second "Add as a copy?") or extend the shell
  dialog. After Replace call `offerUndo` with the previous `StoredQuiz` and its media (as `library.ts remove()` does). Show both dates as
  date + time. Do not navigate on Escape. M.

### M6 · Player: removing a team deletes its scores everywhere at once; restart cannot be undone
- Where: player Teams screen (reachable mid-game from the menu's jump grid and from the host panel), all viewports.
- What: `game/step.ts removeTeam` drops the team, its score in every round and its bonus; the "×" is one tap, no confirm, no Undo (the player
  has no toast). "Start the game again" in the menu is an in-place two-step (first tap changes the label to "Clear all scores and start
  again", stays armed while the menu is open); afterwards all scores are gone with no Undo. This is the only destructive pattern in Quizzard
  that is not the shell's `confirm` (Sheet and the creator use `shell.confirm({danger:true})`).
- Fix: (1) removing a team that has points → a `qp-dialog` confirm ("Remove {{team}}?" / "Its {{n}} points in {{m}} rounds will be lost." /
  Cancel, Remove; Cancel first); no points → remove at once. (2) Restart: a real dialog with the numbers ("Clear {{points}} points of
  {{teams}} teams") and, after it, a 10-second "Scores cleared · Undo" strip above the control bar (keep the previous `GameState` in
  memory). `views/teams.ts`, `ui/menu.ts restartButton`, `ui/dialog.ts`, `game/step.ts`. M.

### M7 · Limits are shown in the wrong unit ("up to 15.7 MB", "Media: 26.6 kB of 262.1 MB")
- Where: picture/audio/video drop areas, the media meter on the quiz card, refusal messages; every language.
  `ux-editor-picture-error-1280-en-light.png`, `ux-round-media-undo-1280-en-light.png`.
- What: `core/src/limits.ts` has `MB = 1024 * 1024` (SPEC: 15 / 50 / 250 MB) but `miniapp/src/format.ts bytesText` divides by `1e6`. People read
  "15.7 MB" / "262.1 MB" as bugs and refusal messages quote numbers that differ from the SPEC and the Help.
- Fix: one unit. Either 1024-based units in `bytesText`, or decimal limits (`15_000_000`, `50_000_000`, `250_000_000`) in `limits.ts`; update the
  unit test. S.

### M8 · The points note is cut off on the stage ("3 точки · 1 за групата, 2 за песента, 3 за двете …")
- Where: Play / audience, question screen, 1280×720 BG (any note longer than ~40 characters; the limit is 80). `ux-p12-reveal-1280-bg.png`.
- What: the points pill is one line with an ellipsis. The note is what SPEC F6/AC3 says the teams must read; the host cannot see it is clipped.
  The round name is clipped the same way ("Кръг за световните ст…").
- Fix: `player/src/render/slide.css` (`[data-slide-points]`, round label): allow two lines (`white-space: normal; line-clamp: 2`,
  `max-inline-size: 60 %`) or put a note longer than ~30 characters on its own line under the pill. M.

### M9 · Player Teams screen on a phone: 12 team names are unreadable and not practically editable
- Where: Play at 360×740, Teams with 12 teams: two columns, each name field ≈ 54 px ("Отбор" for "Отбор 10"). `ux-p12-teams-360-bg.png`.
- Fix: `player/src/styles/views.css .qp-teams`: below 600 px one column for 5+ teams (rows 56 px, the list scrolls in the stage); keep ≤ 4 teams
  in two columns. S.

### M10 · Chip radios fail "visible focus ring on every tab stop" in the automatic check
- Where: a11y-check FAIL 2.4.7, 390 px light: `quiz-kind`, `quiz-answer-type`, `quiz-round-kind`, `quiz-round-answer`.
- What: the radios are `visually-hidden`; the ring is drawn on `.quiz-chip-face` (`ux-focus-chip-390.png`: 2 px purple ring with a white gap,
  visible), so the check is a false positive for sighted keyboard users — but it keeps `a11y-check` red, and a *selected* chip's ring has the
  same colour as its fill (purple on purple), so only the white gap shows it.
- Fix: draw the ring with `:has(input:focus-visible)` on the label in `--color-focus` with `outline-offset: 3px` (a colour different from the
  selected fill), and make the real input a transparent full-size control (`opacity:0; inset:0; position:absolute`) instead of the clipped
  `visually-hidden`, so a checker measures a ring on the focused element. `dom/controls.ts chip()`, `styles/base.css .quiz-chip`. S.

### M11 · Editor: the back link runs off the screen (a 591 px wide button on a 360 px page)
- Where: editor, 360×740, any round name longer than ~25 characters (BG stress data). `ux-stress-editor-360-bg-light.png`.
- What: `.quiz-back` measured at x=12, width 591 px. Its label span has `overflow:hidden; text-overflow:ellipsis` but the button is not constrained, so
  the text is cut by the viewport edge ("…реки, п") and the tap target is wider than the screen. On the round screen the same link ellipsizes correctly.
- Fix: `styles/editor.css`: `.quiz-head { min-width: 0 }` and `.quiz-head .quiz-back { max-width: 100%; min-width: 0 }` (or make `.quiz-head` a grid with
  `grid-template-columns: minmax(0, 1fr)`). S.
